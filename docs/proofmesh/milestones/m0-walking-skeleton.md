# Proofmesh — Milestone M0: Walking Skeleton

- Status: Implementation-ready, pending maintainer go-ahead
- Date: 2026-11-07
- Governing documents: ADR-0001 revision 3, specification revision 3, architecture plan revision 3
- Executes as: one Orbit run in the predecessor repository from a committed baseline
- This document is normative for M0. Where it is more specific than the plan, it wins for M0.

## 1. Goal

Prove the whole Proofmesh path end to end on one small reviewed fixture: capture a TypeScript repository, analyse it through an out-of-process adapter, seal a Meshstore snapshot, answer six read tools over MCP stdio and the HTTP tool API with honest envelopes, and draw a traced path in the Observatory Trace view with its evidence, its horizon, and a table equivalent.

### Non-goals for M0

Incremental indexing, strict freshness, watchers, resumable jobs, cursors, Streamable HTTP MCP, claims and verification, Galaxy, React, Python, Terraform, C#, trust grants, exports, packaging and release, garbage collection, and Windows. Envelopes report each relevant absence as a limitation instead of pretending.

## 2. Preconditions

1. The source packet is materialized in the repository (section 15 lists the paths) and committed on a branch, which is the run's baseline.
2. `/orbit:init` has created `.orbit/config.yaml` in the repository.
3. Node.js `>=22.13` and pnpm 10 are installed. The .NET 10 SDK is installed for the legacy checks.

## 3. Hard constraints

- Do not modify, move, or delete anything under these legacy paths: `.claude-plugin/`, `agents/`, `commands/`, `hooks/`, `skills/`, `config/`, `scripts/`, `src/`, `tests/`, `eval/`, `docs/` except the new `docs/proofmesh/`, the old tool's `.slnx`, `Directory.Build.props`, `Directory.Packages.props`, `global.json`, `.mcp.json`, `README.md`.
- `.gitignore` may gain entries but must not ignore anything under `fixtures/`. In particular `fixtures/ts-invoicing/repo/packages/billing/dist/invoice.js` must stay tracked.
- Production dependencies must pass `policy/licenses.json`.
- No network access at runtime. No telemetry. No remote fonts, scripts, or styles in Observatory.
- No code reads or indexes any repository other than the fixture during the run. The private-codebase smoke run (section 13) is performed by the integrator after the run, not by workers.
- Snapshot files contain no wall-clock timestamps and no random values.
- Expected facts in `fixtures/ts-invoicing/expected.json` are written by hand as given in section 11. They are never generated by Proofmesh.

## 5. Identifiers and hashing

All hashes are SHA-256, lowercase hex. `h(x)` means the hash of the UTF-8 bytes of `x`. Canonical JSON means keys sorted, no insignificant whitespace.

| ID | Derivation |
|---|---|
| Repository | `repo_` + first 12 hex of `h(realpath(root))` |
| Snapshot | `snap_` + first 24 hex of `h(canonical identity)`; identity = `{repository_id, manifest_hash, config_hash, analysis_mode, adapters: [manifests sorted by id], format_version: "0.1"}` |
| Manifest hash | `h` of lines `"<path>\t<content_hash or ->\t<discovery_status>"`, sorted by path, joined with `\n`; `discovery_status` is `capture`, `excluded:<rule>`, `unsupported:<detail>`, or `failed:<code>`, all known before analysis |
| File | `file_` + first 24 hex of `h(snapshot_id + "\n" + path)` |
| Symbol | `sym_` + first 24 hex of `h(snapshot_id + "\n" + path + "\n" + kind + "\n" + qualified_name + "\n" + start_byte)` |
| External symbol | `ext_` + first 24 hex of `h(module + "\n" + name)` |
| Evidence | `ev_` + first 24 hex of `h(object_hash + "\n" + start_byte + "\n" + end_byte + "\n" + extractor)` |
| Assertion (calls) | `as_` + first 24 hex of `h(snapshot_id + "\ncalls\n" + source_id + "\n" + site_path + "\n" + site_start_byte)` |
| Assertion (imports) | `as_` + first 24 hex of `h(snapshot_id + "\nimports\n" + source_file_id + "\n" + target_file_id)` |
| Query | `q_` + 16 random base-32 lowercase characters (envelopes only) |

Paths are repository-relative, forward slashes, NFC-normalized, case preserved.

## 6. Storage

### Data directory

Resolution order: `--data-dir`, then `PROOFMESH_DATA_DIR`, then `~/.proofmesh`. `proofmesh init` creates it with mode 0700, creates `catalog.db`, and writes `tokens/api` (32 random bytes, hex, mode 0600). Every other command fails with a clear message if the directory is not initialized.

### Catalog DDL (`schemas/catalog/0001.sql`)

```sql
PRAGMA journal_mode = WAL;
CREATE TABLE schema_migration (version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL) STRICT;
CREATE TABLE repository (
  id TEXT PRIMARY KEY, root TEXT NOT NULL UNIQUE, name TEXT NOT NULL, created_at TEXT NOT NULL
) STRICT;
CREATE TABLE snapshot (
  id TEXT PRIMARY KEY,
  repository_id TEXT NOT NULL REFERENCES repository(id),
  state TEXT NOT NULL CHECK (state IN ('staging','published','failed','retired')),
  identity_hash TEXT NOT NULL,
  store_digest TEXT,
  analysis_mode TEXT NOT NULL CHECK (analysis_mode IN ('no_execution','trusted_build')),
  created_at TEXT NOT NULL, published_at TEXT, failure TEXT,
  CHECK ((state = 'published') = (store_digest IS NOT NULL AND published_at IS NOT NULL))
) STRICT;
CREATE TABLE current_snapshot (
  repository_id TEXT PRIMARY KEY REFERENCES repository(id),
  snapshot_id TEXT NOT NULL REFERENCES snapshot(id)
) STRICT;
CREATE TABLE index_lease (
  singleton INTEGER PRIMARY KEY CHECK (singleton = 1), owner TEXT NOT NULL, expires_at TEXT NOT NULL
) STRICT;
```

### Snapshot DDL (`schemas/snapshot-format/0.1.sql`)

```sql
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL) STRICT;
-- keys: format_version, snapshot_id, repository_id, identity (canonical JSON), analysis_mode, adapters (JSON)
CREATE TABLE file (
  id TEXT PRIMARY KEY, path TEXT NOT NULL UNIQUE, content_hash TEXT, size INTEGER NOT NULL,
  language TEXT,
  disposition TEXT NOT NULL CHECK (disposition IN ('indexed','excluded_by_rule','unsupported','failed','pending')),
  disposition_detail TEXT,
  capabilities TEXT NOT NULL CHECK (json_valid(capabilities)),
  CHECK ((disposition = 'indexed') = (content_hash IS NOT NULL))
) STRICT;
CREATE TABLE evidence (
  id TEXT PRIMARY KEY, file_id TEXT NOT NULL REFERENCES file(id), object_hash TEXT NOT NULL,
  start_byte INTEGER NOT NULL, end_byte INTEGER NOT NULL, start_line INTEGER NOT NULL, end_line INTEGER NOT NULL,
  source_kind TEXT NOT NULL CHECK (source_kind IN ('declaration','call_site','import_statement')),
  extractor TEXT NOT NULL, extractor_version TEXT NOT NULL,
  analysis_mode TEXT NOT NULL CHECK (analysis_mode IN ('no_execution','trusted_build')),
  CHECK (start_byte >= 0 AND end_byte > start_byte AND end_line >= start_line)
) STRICT;
CREATE TABLE symbol (
  id TEXT PRIMARY KEY, file_id TEXT NOT NULL REFERENCES file(id),
  kind TEXT NOT NULL CHECK (kind IN ('function','class','method','interface','type_alias','variable')),
  name TEXT NOT NULL, qualified_name TEXT NOT NULL,
  start_byte INTEGER NOT NULL, end_byte INTEGER NOT NULL, start_line INTEGER NOT NULL, end_line INTEGER NOT NULL,
  signature TEXT, stable_key TEXT NOT NULL, evidence_id TEXT NOT NULL REFERENCES evidence(id)
) STRICT;
CREATE TABLE external_symbol (id TEXT PRIMARY KEY, module TEXT NOT NULL, name TEXT NOT NULL) STRICT;
CREATE TABLE assertion (
  id TEXT PRIMARY KEY,
  type TEXT NOT NULL CHECK (type IN ('calls','imports')),
  origin TEXT NOT NULL CHECK (origin IN ('syntax','semantic_resolver')),
  resolution TEXT NOT NULL CHECK (resolution IN ('resolved','resolved_external','candidate','ambiguous','unresolved')),
  source_kind TEXT NOT NULL CHECK (source_kind IN ('symbol','file')), source_id TEXT NOT NULL,
  target_kind TEXT CHECK (target_kind IN ('symbol','file','external')), target_id TEXT,
  reason TEXT, adapter TEXT NOT NULL, adapter_version TEXT NOT NULL,
  analysis_mode TEXT NOT NULL CHECK (analysis_mode IN ('no_execution','trusted_build')),
  CHECK ((resolution IN ('resolved','resolved_external')) = (target_id IS NOT NULL)),
  CHECK ((resolution = 'resolved_external') = (target_kind IS 'external')),
  CHECK ((resolution IN ('resolved','resolved_external')) OR reason IS NOT NULL)
) STRICT;
CREATE TABLE assertion_evidence (
  assertion_id TEXT NOT NULL REFERENCES assertion(id), evidence_id TEXT NOT NULL REFERENCES evidence(id),
  PRIMARY KEY (assertion_id, evidence_id)
) STRICT, WITHOUT ROWID;
CREATE TABLE assertion_candidate (
  assertion_id TEXT NOT NULL REFERENCES assertion(id), symbol_id TEXT NOT NULL REFERENCES symbol(id),
  rank INTEGER NOT NULL, reason TEXT NOT NULL, PRIMARY KEY (assertion_id, symbol_id)
) STRICT, WITHOUT ROWID;
CREATE TABLE edge (
  src TEXT NOT NULL, type TEXT NOT NULL, dst TEXT NOT NULL, resolution TEXT NOT NULL,
  assertion_id TEXT NOT NULL REFERENCES assertion(id),
  PRIMARY KEY (src, type, dst, assertion_id)
) STRICT, WITHOUT ROWID;
CREATE INDEX edge_by_dst ON edge (dst, type, src);
CREATE VIRTUAL TABLE symbol_fts USING fts5(symbol_id UNINDEXED, name, qualified_name, tokenize = 'trigram');
```

`edge` holds exactly one row per `resolved` or `resolved_external` assertion, with `src`, `dst`, and `resolution` equal to the assertion's. A validation step enforces this before sealing.

### Evidence store

Objects live at `objects/sha256/<first 2>/<next 2>/<hash>`, mode 0444. Write to a temporary file in `objects/tmp/`, fsync, hash, rename. A store operation returns only after the hash is verified. An evidence record's range must lie within its object's size.

### Sealing and publication

1. Facts are written to `staging/<snapshot-id>/snapshot.db`.
2. Validation, all of which must pass: every file has one disposition; every symbol, assertion, and evidence reference resolves; every evidence object exists and its range fits; the `edge` and `assertion` correspondence holds; the FTS row count equals the symbol count; `PRAGMA integrity_check` and `PRAGMA foreign_key_check` report nothing.
3. `PRAGMA journal_mode = DELETE`, close, fsync.
4. Compute the file's SHA-256 (`store_digest`), set mode 0444.
5. Rename to `snapshots/<snapshot-id>.db`, fsync the `snapshots/` directory.
6. One catalog transaction: `state = 'published'`, `store_digest`, `published_at`, upsert `current_snapshot`.
7. Remove `staging/<snapshot-id>/`.

Fault injection, honored only when `PROOFMESH_FAULT_POINT` is set: `before_rename` exits with code 70 after step 4; `after_rename` exits with code 70 after step 5. Either way the current pointer is unchanged.

Opening a snapshot for a query: look up the published row and its digest, open the file read only with `query_only`, and verify the digest the first time the process opens that snapshot. A mismatch yields `SNAPSHOT_UNAVAILABLE` with detail `digest_mismatch`.

Identity is computed after discovery, capture, and adapter `initialize`, before any `analyze` call. If it matches an already published snapshot, `index` reports `unchanged`, shuts the adapter down, and writes nothing. Final dispositions are a deterministic function of the identity's inputs, so they need not be part of it.

## 7. Discovery

- Walk the registered root. Never follow symlinks; record each as `unsupported` with detail `symlink_not_followed`.
- The `.git` directory is repository metadata, not content, and is outside the inventory.
- Default exclusion rules, applied to repository-relative paths: `**/node_modules/**`, `**/dist/**`, `**/build/**`, `**/bin/**`, `**/obj/**`. Every file under a matching path is still listed (by `lstat`, contents never read) and is `excluded_by_rule` with the rule as detail, so the inventory stays complete.
- Files larger than 1 MiB are `excluded_by_rule` with detail `max_file_bytes:1048576`.
- Files with a NUL byte in their first 8 KiB are `unsupported` with detail `binary`.
- Language by extension: `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs` are TypeScript-adapter languages; `tsconfig.json` and `jsconfig.json` are adapter configuration. Every other file is `unsupported` with detail `no_adapter:<extension or name>`.
- Unreadable files are `failed` with the error code as detail.
- Git metadata is recorded only when the root itself is the top level of a Git work tree. Otherwise `git: {available: false, reason: "root_is_not_worktree_top"}` or `"no_git"`.
- Each TypeScript-language or configuration file is captured into the evidence store and becomes `indexed` once the adapter reports it, or `failed` if the adapter reports a failure for it.

## 8. Adapter protocol v0

Transport: JSON-RPC 2.0, one JSON object per line. Requests on the adapter's stdin, responses on its stdout, logs on stderr. The core validates every message against `schemas/adapter-protocol/`.

`initialize` request params:

```json
{
  "protocol_version": "0.1",
  "workspace": "/abs/path/to/staging/<snapshot-id>/workspace",
  "analysis_mode": "no_execution",
  "files": [{"path": "packages/format/src/currency.ts", "content_hash": "…", "language": "typescript"}]
}
```

`initialize` result:

```json
{
  "adapter": {"id": "typescript", "version": "0.1.0", "protocol_version": "0.1",
              "languages": ["typescript", "javascript"], "toolchain": {"typescript": "<pinned version>"}},
  "capabilities": {"syntax": true, "symbols": true, "imports": true, "resolved_calls": true,
                   "references": false, "framework": false},
  "external_inputs": []
}
```

`analyze` request params: `{"paths": ["…"]}`, at most 200 paths. Result:

```json
{
  "symbols": [{"local_id": "s1", "path": "…", "kind": "function", "name": "formatAmount",
               "qualified_name": "packages/format/src/currency:formatAmount",
               "range": {"start_byte": 0, "end_byte": 120, "start_line": 1, "end_line": 3},
               "signature": "formatAmount(cents: number, currency: string): string"}],
  "relationships": [{"type": "calls", "origin": "semantic_resolver",
                     "source": {"symbol": "s3"},
                     "site": {"path": "…", "range": {"start_byte": 0, "end_byte": 0, "start_line": 9, "end_line": 9}},
                     "resolution": "resolved", "target": {"symbol": "s1"}}],
  "file_results": [{"path": "…", "status": "ok", "capabilities": {"syntax": "complete", "symbols": "complete",
                    "imports": "complete", "resolved_calls": "complete", "references": "unsupported",
                    "framework": "unsupported"}}],
  "diagnostics": []
}
```

Rules for the TypeScript adapter:

- Pin the `typescript` package to 6.x. Version 7.x no longer exports the classic compiler API (verified 2026-11-07 with `typescript@7.0.2`).
- Build one program from the workspace's `tsconfig.json` (or the listed files if none) with the compiler API. Never load language-service plugins, never resolve outside the workspace except the TypeScript library declarations, never run scripts.
- Symbols: one `module` symbol per TypeScript file (amendment A5; name = file name, qualified name = path without extension, range = the whole file), top-level and namespace-level function declarations, classes and their methods, interfaces, type aliases, and module-level variable statements (`kind: "variable"`, range = the whole statement; `kind: "function"` when the initializer is an arrow function or function expression, per A5). Calls inside nested functions belong to the enclosing symbol; top-level calls belong to the module symbol.
- `qualified_name` = path without extension + `:` + the name chain (`Class.method`). `signature` = name + `checker.signatureToString` for functions and methods; null otherwise.
- Ranges: the declaration node without leading trivia, including modifiers such as `export`. Offsets are UTF-8 byte offsets; convert from the compiler's UTF-16 positions.
- `calls`: every call and `new` expression inside a symbol. Resolve the callee with the checker, following aliases (`getAliasedSymbol`) to the declaration. Declaration in the workspace → `resolved` to that symbol. Declaration in a library file → `resolved_external` with `target: {"external": {"module": "<declaration file basename>", "name": "<checker.getFullyQualifiedName>"}}`. Callee is an element access with a non-literal argument → `unresolved`, reason `dynamic_element_access`. No symbol for any other reason → `unresolved`, reason `no_symbol`. More than one declaration in the workspace → `ambiguous` with candidates.
- `imports`: every `import … from` and `export … from` statement, resolved to the target file with the compiler's module resolution, one relationship per statement with `source: {"file": "<path>"}` and `target: {"file": "<path>"}`. The core merges statements between the same two files into one assertion with one evidence record per statement.
- `site.range` for a call covers the whole call expression; for an import, the whole statement.

The core assigns IDs, creates evidence records by slicing captured objects, and rejects any range that does not fit.

Supervision: 60 s per request; on a crash, restart once and retry the batch; a second failure marks the batch's files `failed` with detail `adapter_crash` and the snapshot fails validation.

## 9. Tools

Six read tools, identical over MCP stdio and `POST /api/v1/tools/<tool>`.

### Common input

```json
{"repository_id": "repo_…", "snapshot_id": null,
 "limits": {"timeout_ms": 10000, "max_rows": 100, "max_bytes": 65536, "max_depth": 6}}
```

`repository_id` may be omitted when exactly one repository is registered. `freshness` is not accepted in M0; passing it yields `INVALID_ARGUMENT` with detail `strict_freshness_not_available`.

| Limit | Default | Server maximum |
|---|---|---|
| `timeout_ms` | 10000 | 30000 |
| `max_rows` | 100 | 1000 |
| `max_bytes` | 65536 | 1048576 |
| `max_depth` | 6 | 12 |

Values above the maximum are clamped, and the envelope reports both requested and applied values plus a limitation naming the clamp.

### Envelope (`schemas/envelope.schema.json`)

```json
{
  "schema_version": "0.1",
  "query_id": "q_…",
  "tool": "find_symbols",
  "snapshot": {"id": "snap_…", "repository_id": "repo_…", "analysis_mode": "no_execution", "published_at": "…"},
  "freshness": {"mode": "snapshot", "status": "as_of_snapshot"},
  "coverage": {
    "inventory_complete": true,
    "files_discovered": 10,
    "dispositions": {"indexed": 7, "excluded_by_rule": 1, "unsupported": 2, "failed": 0, "pending": 0},
    "capabilities": {"text": "complete", "syntax": "complete", "symbols": "complete", "imports": "complete",
                     "references": "unsupported", "resolved_calls": "partial", "framework": "unsupported"}
  },
  "data": {},
  "evidence_ids": [],
  "unresolved": {"count": 0, "scope": "query", "sample": []},
  "completion": {"truncated": false, "stop_reasons": [], "timed_out": false, "next_cursor": null},
  "limits": {"requested": {}, "applied": {}},
  "limitations": []
}
```

- Capability values: `complete`, `partial`, `unsupported`, `failed`, `not_run`. Snapshot-level values aggregate indexed files: all complete → `complete`; any partial, or a mix → `partial`; none applicable → `unsupported`.
- `stop_reasons` values: `max_rows`, `max_depth`, `max_bytes`, `timeout`.
- `unresolved.sample` holds at most 20 entries of `{assertion_id, reason, file, line}`.
- Every M0 envelope includes the limitation `"References other than calls and imports are not analysed in this version."`. When `truncated` is true it also includes `"Results were truncated and continuation is not available in this version."`.
- Errors use `schemas/error.schema.json`: `{"error": {"code": "<taxonomy code>", "message": "…", "details": {}}}`. Over MCP they are tool results with `isError: true` and the error as structured content. Over HTTP they use status 400, 401, 403, 404, 409, or 500 with the same body.

### Tool data shapes

`workspace_status`, no extra input:

```json
{"repository": {"id": "repo_…", "name": "repo", "git": {"available": false, "reason": "root_is_not_worktree_top"}},
 "adapters": [{"id": "typescript", "version": "0.1.0", "protocol_version": "0.1", "languages": ["typescript","javascript"]}],
 "files": [{"path": "README.md", "disposition": "unsupported", "detail": "no_adapter:.md", "language": null,
            "capabilities": {}}]}
```

`files` is sorted by path and bounded by `max_rows`; coverage counts are always exact.

Use the SDK's low-level server so each tool's `inputSchema` is the file in `schemas/tools/` unchanged.

`find_symbols`, input `{"text": "<1..200 chars>", "kinds": [..]?}`: substring match on `name` or `qualified_name`, case-insensitive (FTS trigram for 3 or more characters, a scan with `instr` below that). Order: exact name match, then name prefix, then the rest; ties by `qualified_name`. Data: `{"symbols": [{"id", "kind", "name", "qualified_name", "path", "start_line", "end_line", "signature"}]}`.

`get_symbol`, input `{"symbol_id"}`: data `{"symbol": {…same fields…, "evidence_id"}}`; `evidence_ids` holds the declaration evidence.

`get_relationships`, input `{"subject_id": "sym_…|file_…", "direction": "in|out|both" (default both), "types": [..] (default ["calls"] for symbols, ["imports"] for files), "resolutions": [..] (default all five)}`. Data:

```json
{"relationships": [{"assertion_id": "as_…", "type": "calls", "direction": "out", "resolution": "resolved",
                    "origin": "semantic_resolver",
                    "other": {"kind": "symbol", "id": "sym_…", "name": "formatAmount",
                              "qualified_name": "packages/format/src/currency:formatAmount", "path": "…"},
                    "site": {"path": "…", "start_line": 9, "end_line": 9},
                    "reason": null, "evidence_ids": ["ev_…"]}],
 "boundaries": [{"assertion_id": "as_…", "reason": "dynamic_element_access", "path": "…", "line": 11,
                 "from_id": "sym_…"}]}
```

`other.kind` is `symbol`, `file`, `external` (with `module` and `name`), or `none` for unresolved. For `direction` `in` or `both` on a symbol, `boundaries` lists every `unresolved`, `candidate`, and `ambiguous` calls assertion in the snapshot whose target is unknown, because any of them could call the subject; `unresolved.count` (scope `query`) equals its length. `resolved_external` sites never appear as inbound boundaries, because their targets are known.

`trace_paths`, input `{"source_id", "target_id", "types": ["calls"], "resolutions": ["resolved"]}` with `max_depth` from limits. Direction is outbound. Data:

```json
{"conclusion": "path_found | no_path_within_bounds | no_resolved_path | no_path_exhaustive",
 "paths": [{"nodes": ["sym_…"], "assertions": ["as_…"]}],
 "search": {"levels": [{"depth": 1, "frontier": 1, "expanded_edges": 1}],
            "stopped_by": null,
            "horizon": [{"id": "sym_…", "unexplored_edges": 1}]},
 "boundaries": [{"assertion_id": "as_…", "reason": "dynamic_element_access", "from_id": "sym_…", "path": "…", "line": 11}],
 "nodes": {"sym_…": {"kind": "function", "name": "…", "qualified_name": "…", "path": "…", "start_line": 1}}}
```

Semantics: level-synchronous breadth-first search from the source over `edge` rows matching `types` and `resolutions`. All shortest paths are returned, up to `max_rows`. `boundaries` lists unresolved, candidate, and ambiguous calls assertions whose source is an expanded node. Conclusions:

- `path_found`: at least one path.
- `no_path_within_bounds`: a limit stopped the search; `stopped_by` names it, `horizon` lists unexpanded frontier nodes with their count of matching outbound edges, `completion.truncated` is true. The limitation reads `"No path was found within the limits. This is not evidence that no path exists."`.
- `no_resolved_path`: the search exhausted reachable nodes without a limit, and `boundaries` is not empty. The limitation reads `"Unresolved call sites in the explored region could lead to the target."`.
- `no_path_exhaustive`: the search exhausted reachable nodes without a limit and found no boundaries. The limitations read `"Exhaustive only for the declared relationship types and resolutions in this snapshot."` and `"Calls made from code outside the repository, such as library callbacks, are not modelled."`.

`read_evidence`, input `{"evidence_ids": [1..50]}`. Data:

```json
{"evidence": [{"id": "ev_…", "path": "…", "start_line": 9, "end_line": 9, "start_byte": 0, "end_byte": 0,
               "object_hash": "…", "source_kind": "call_site", "extractor": "typescript", "extractor_version": "0.1.0",
               "analysis_mode": "no_execution",
               "integrity": {"status": "verified"}, "text": "formatAmount(cents, currency)"}]}
```

Integrity: re-hash the object on every read. Missing object → `{"status": "unavailable"}` and `text: null`. Hash mismatch → `{"status": "failed", "actual_hash": "…"}` and `text: null`. Text is the exact UTF-8 slice. Unknown IDs yield `NOT_FOUND` for the whole call.

## 10. CLI, HTTP, and Observatory

### CLI

| Command | Behavior |
|---|---|
| `proofmesh init [--data-dir D]` | Create and initialize the data directory |
| `proofmesh repo add <path> [--name N]` | Register a root; print the repository ID; idempotent |
| `proofmesh index <repository-id or path>` | Run the coordinator; print snapshot ID, `published` or `unchanged`, and coverage counts; exit 0 on publish or unchanged, 1 on failure |
| `proofmesh status [repository] [--json]` | `workspace_status` as text or JSON |
| `proofmesh mcp` | MCP server on stdio; logs to stderr only |
| `proofmesh view [--port P] [--no-open]` | Loopback HTTP server and Observatory; prints the launch URL; `--port 0` picks a free port |
| `proofmesh debug dump --normalized <snapshot-id>` | JSON Lines of every snapshot table, rows sorted by primary key, tables sorted by name, `meta` excluded |

Logging: JSON lines to stderr, level from `PROOFMESH_LOG_LEVEL` (default `info`); never source content.

### HTTP

- Binds `127.0.0.1` only. Rejects requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` with 403.
- `GET /` and static assets: no authentication, every response carries the CSP from plan section 12 plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`.
- `POST /session` with `{"token": "…"}`, with an `Origin` equal to the server origin: the token printed by `proofmesh view` for this launch, single use, valid for 10 minutes. Success sets `pm_session` (HttpOnly, SameSite=Strict, Path=/, no Expires) and returns 204. A reused or unknown token returns 401.
- `POST /api/v1/tools/<tool>`: requires `pm_session` and an `Origin` equal to the server origin; otherwise 401 or 403. Body and response as in section 9.
- The launch URL is `http://127.0.0.1:<port>/#t=<token>`. The page exchanges the fragment token and then removes the fragment with `history.replaceState`.

### Observatory: Trace view

- Layout: dark theme by default, light theme via `prefers-color-scheme`. Header with repository, snapshot ID, publication time, and the analysis mode. Left panel with coverage counts and a table-view toggle. Center canvas. Right evidence panel. Footer with the conclusion sentence.
- Inputs: source and target symbol pickers backed by `find_symbols` (every candidate shows its `qualified_name` and path), a depth control from 1 to 12, and a Trace button.
- Rendering with Sigma.js and graphology, from a pure scene-model function `toScene(envelope)` that returns nodes and edges with style keys. Layout: x by search depth, y by order within the depth. Style keys: `resolved` (solid, arrowhead), `resolved_external` (dashed, to a small hollow node), `unresolved` (short frayed stub to a fog blob labelled with the reason), `horizon` (dashed ring on the node).
- Overlays as DOM elements, so they are testable and readable by assistive technology: a horizon badge per horizon node reading `+<n> unexplored · stopped by <reason>`, and a legend that includes `Position carries no meaning.`.
- Motion: edges reveal level by level, 120 ms apart; nodes on the path carry a soft glow. Under `prefers-reduced-motion`, nothing animates and the body carries `data-motion="reduced"`.
- Clicking a node opens `get_symbol` and `read_evidence` for its declaration; clicking an edge opens the assertion's evidence. The panel shows path, lines, extractor, origin, resolution, analysis mode, a short hash, and an integrity badge, and renders text through text nodes only. Bidirectional control characters (U+202A–U+202E, U+2066–U+2069) and zero-width characters (U+200B–U+200F, U+FEFF) display as `⟨U+XXXX⟩` tokens.
- Table view: the same facts as an ordered table (path nodes, edges with resolution, boundaries, horizon, conclusion), fully keyboard navigable.
- If WebGL is unavailable, the table view opens with a notice.

Pass conditions:

- Every `.cs` file is `unsupported` with detail `no_adapter:.cs`, and the envelope's `symbols` capability is `unsupported`. M0 says plainly that it cannot analyse C#.

## 14. Stop conditions

The worker stops and reports, without working around the problem, when:

- The bundled SQLite lacks FTS5 with the trigram tokenizer, STRICT tables, or JSON functions.
- The pinned TypeScript prints a signature or library name differently from `expected.json`.
- A required production dependency fails the license policy.
- Meeting a criterion needs a schema, ID, or envelope change beyond this document, a change under a legacy path, or reading anything outside the fixture.
- A criterion appears to conflict with another criterion or with the ADR.
