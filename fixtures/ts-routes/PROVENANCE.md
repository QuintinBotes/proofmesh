# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code, and neither `express` nor `@nestjs/common` is installed: the rules recognise both by the module their imports name, so the fixture needs no package.

`expected.json` is hand-written from the fixture code and never generated by Proofmesh. Endpoints are named as the C# rules name them: the verb (`ANY` for Express's `all`), then the path without outer slashes, each Express or NestJS `:param` written `{param}` and a regular-expression constraint such as `(\d+)` dropped.

Express. `src/app.ts` makes the application with `express()` and mounts three routers. `src/routes/orders.ts` is an `express.Router()` exported by default and mounted at `/api/orders`; its routes take an inline handler (which becomes a function symbol named after its registration), a named function, middleware before the handler, and a handler wrapped in a call (`guard(cancel)`), which leaves the module that registers it as the code the endpoint exposes. `src/routes/admin.ts` mounts the router `reports` on the router `admin`, which the application mounts at `/admin`, so `reports.get('/daily')` is `GET admin/reports/daily`; its `'/' + PERIOD` route is built from a variable and stays unresolved. `src/routes/legacy.ts` holds a router mounted under a prefix held in a variable (`VERSION`) and a router nothing mounts; both stay unresolved. `app.get('env')` reads a setting and is no route.

NestJS. `src/inventory/inventory.controller.ts` holds `@Controller('inventory')` with `@Get(':sku')`, `@Post()`, a `@Put` with two paths, a `@Delete` whose path is a constant (unresolved) and an undecorated method, and `@Controller()` with `@Get('status')`.

Decoys. `src/decoys.ts` calls `get` on an object literal and on what a local `Router` factory (`src/router.ts`, which shares Express's name) returns; neither registers a route or makes a function symbol.

`links` is the `http_route` part of the link file for a workspace of `fixtures/cs-links/repo-a` (named `store`, a Refit client calling `GET api/orders/{orderId}` and `GET inventory/{sku}`) and this repository (named `shop`): the Express route and the NestJS route each match one client method exactly.
