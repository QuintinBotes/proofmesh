# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code, and none of the test frameworks is installed and nothing is compiled: a marker is recognised by the name it is written with, as a reader of the file sees it.

One code file and one test per language, as the test-recognition work (issue 11) lists them:

| Language | Code | Test |
|---|---|---|
| Go | `calc/calc.go` | `calc/calc_test.go`: `TestAdd`, `BenchmarkAdd`, `ExampleAdd`, and the helper `setup` |
| Rust | `src/lib.rs` `add` | the same file, in a `#[cfg(test)] mod tests`: `adds` |
| Python | `pkg/calc.py` | `pkg/test_calc.py`: `test_add`, and the helper `make` |
| Java | `src/main/java/a/Calc.java` | `src/test/java/a/CalcTest.java`: `@Test adds`, and the helper `make` |
| Kotlin | `src/main/kotlin/Calc.kt` | `src/test/kotlin/CalcTest.kt`: `@Test adds`, and the helper `make` |
| PHP | `src/Calc.php` | `src/CalcTest.php`: a `TestCase` with `testAdd` and the helper `make` |
| Ruby | `lib/calc.rb` | `spec/calc_spec.rb`: `it "adds"`, and the helper `make` |
| C++ | `calc.cc` | `calc_test.cc`: `TEST(Calc, Adds)`, and the helper `make` |
| Swift | `Sources/Calc.swift` | `Sources/CalcCheck.swift`: an `XCTestCase` with `testAdd` and the helper `make`, outside any `Tests` directory |

`expected.json` is hand-written from the fixture code and never generated by Proofmesh. `roles` lists the symbols that are test entry points (role `test`); `test_support` lists symbols that are test code without being entry points, by their scope (the `tests` module of the Rust file, the `XCTestCase` class and its helper); `files` lists the files test-file conventions recognise.
