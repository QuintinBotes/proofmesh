# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code, and neither `@prisma/client` nor `express` is installed: the rules recognise both by the module their imports name, so the fixture needs no package.

`expected.json` is hand-written from the fixture code and never generated by Proofmesh.

The schema. `prisma/schema.prisma` declares `User` (`@@map("users")`, `@@schema("auth")`), `Order` (`@@map(name: "orders")`, `@@schema("sales")`) and `AuditEntry` (no `@@map`, so its table is the model's name, in `sales`). `User` holds a comment and a default string that contain a closing brace and an `@@map`; neither ends the model or names its table. The syntax tier declares each table at its mapping, as for `fixtures/prisma-schema`.

The client (A36). `src/db.ts` exports a module-level `new PrismaClient()`. `src/users.ts` imports it: `listUsers` calls `prisma.user.findMany`, `recentAudit` calls `prisma.auditEntry.findMany`, and `countInvoices` calls `prisma.invoice.count`, an accessor no model has, which stays unresolved (`unknown_name`). `src/orders.ts` holds `OrderService`, whose constructor parameter property `prisma` is typed `PrismaClient`; its method `place` calls `this.prisma.order.create`. Each model access references its model's table from the enclosing function or method; the TypeScript adapter declares each table at its first access in path order, so `sales.orders` is declared in `src/orders.ts` and `auth.users` and `sales.AuditEntry` in `src/users.ts`.

The endpoints. `src/routes.ts` is an `express.Router()`, exported by default and mounted at `/api` by the application in `src/app.ts`. `GET api/users` runs an inline handler that calls `listUsers`; `POST api/orders` runs `placeOrder`, which calls `place` on a module-level `OrderService`. So each endpoint reaches its table in three hops: the handler, the function or method that accesses the model, the table.

Decoys. `src/decoys.ts` declares its own class named `PrismaClient` and calls `local.user.findMany()` on an instance, calls `cache.order.create(1)` on an object literal, and calls `prisma.$metrics.json()` on the real client, whose `$`-prefixed members are not models. None is a model access.

Subclassed clients. `src/worker/prisma.service.ts` declares `PrismaService extends PrismaClient`, the NestJS pattern, and `AuditedPrisma extends PrismaService`. `src/worker/audit.ts` reaches `auditEntry` through a constructor parameter typed `PrismaService` (line 7) and `user` through a module-level `new AuditedPrisma()` (line 14). Both files sort after `src/users.ts`, so each table is still declared at its first access there.
