# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code. The Rosetta suite (issue 20, FR211 to FR220): one small program of shapes, written in the idiom of each of ten languages, and the rows each tier is expected to answer.

- `contract.json` is written by hand: the eight calls, the rows a complete answer holds, and the lean grammar each call may use. It does not depend on any one language.
- Each `<language>/expected.json` is written by hand from that language's program and from the documented behaviour of its tier (`docs/proofmesh/languages.md`), line by line: a row's line is the line of the declaration or call in the program. It is never generated by or pasted from the output of the code under test. A row the tier does not give is listed under `not_at_tier` with the reason the documentation or the language gives; a row beyond the contract is an `extra` with its reason. While the suite was written an exploratory run showed the names the tiers give symbols and the form of a lean row; every expected row was then written by hand and checked against the program's own lines (a row's line is the line of the declaration or call), and a gap or an extra is recorded only where the documented rules of the tier explain it.
- The programs are not built or run: several would not compile without their toolchain's packages (the test frameworks are not installed), and Proofmesh reads them as text.
- A change to a row in an `expected.json` is made in the pull request of the slice whose behaviour changed it, and says which slice. A tier that a later slice adds to a language (a SCIP index for Go, say) adds a section beside the existing one and edits no other section.
