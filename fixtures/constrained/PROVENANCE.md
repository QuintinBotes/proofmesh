# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code. A Go workspace of three modules (`svc` requires `lib` and not `other`) and a Maven reactor of two modules (`b` depends on `a`, `a` on nothing), written to hold same-named declarations where only the module graph, the imports or the visibility rules tell the right one from the wrong one (issue 16, FR171 to FR180). Several files do not compile on purpose: a call into a module the caller does not declare, an unexported name used from another package.

The Kotlin, PHP and Ruby trees (FR880 to FR890) follow the same aim: a Gradle build of three modules (`app` depends on `lib`, not on `other`); a Composer project `acme/shop` whose PSR-4 map puts `Shop\` in `src/`, a stray copy of one of its classes in `legacy/`, and a project `acme/plugin` that `acme/shop` does not require; and Ruby files that require each other beside a file of a class of the same name that nothing requires. Some calls fail on purpose: an `internal` or `private` function from outside, a class of an undeclared module or project, a private method from outside its class.
