# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code: `Microsoft.Extensions.DependencyInjection` and its HttpClient extensions are minimal stand-ins in `repo-a/src/StandIns`, so the fixture needs no package.

Two repositories for cross-repository service links (A7). `repo-a` is registered as `storefront`: it registers named HTTP clients, `orders-service` twice (plain and typed, so one `service` symbol), `catalog-api` through a `const` declared in another file, and a name read from the environment, which stays unresolved. A typed client registered without a name names no service. `repo-b` is registered as `orders`; `.contoso/api-clients.yaml` is its service registry, listing the callers it grants: `storefront-web` with the repository `storefront` (an exact repository name), `Storefront-Api` (a name that matches `storefront` as a service name does), `reporting` (no member of the workspace), and `orders` (the registry's own repository, which links nothing).

`expected.json` is hand-written from the fixture code and never generated by Proofmesh. The `service_name` rule matches `orders-service` to `orders` at 0.7, its fixed confidence for a name match, and leaves `catalog-api` as a boundary.
