# Provenance

Project-authored for Proofmesh. Apache-2.0. No third-party code. Three repositories for the links from cloud resources to the services that deploy to or use them (A8, A35). `repo-infra` holds Terraform and a small Pulumi TypeScript program: a web app named `orders-api` (a service-name match for `orders`), a container app whose name names nothing but whose image names `storefront`, a Lambda function naming nothing in the workspace, a Service Bus topic `orders.placed`, an SNS topic `Orders.Shipped` (a match ignoring case), a queue whose name is a variable whose default is `orders.placed` (not a literal, so never matched), and a Pulumi web app whose logical name is `orders-web` and whose `name` argument is `orders`. The test installs minimal stand-ins for `@pulumi/pulumi` and `@pulumi/azure-native` into a temporary copy. `repo-orders` is a C# service that publishes `orders.placed` and `orders.audit` and consumes `orders.shipped` through a Kafka stand-in, and declares its own `orders.audit` queue. `repo-storefront` declares its own web app named `storefront`. A resource declared in the repository whose service or channel it names needs no link. The expected links in `expected.json` are written by hand; an unresolved link's confidence is 1, the certainty that nothing in the workspace matched.

The two `depends_on_package` rows with reason `no_match` in `expected.json` are the npm packages `repo-infra/package.json` declares (`@pulumi/pulumi`, `@pulumi/azure-native`), which no member of the workspace builds. They are written by hand from that manifest, the way `fixtures/cs-links` records an unmatched NuGet package (FR127).
