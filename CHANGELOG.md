# Changelog

All notable changes are listed here. The format follows Keep a Changelog; versions follow semantic versioning.

## Unreleased

The Galaxy's layout is computed with the snapshot, and every symbol keeps its place (part of #44; FR1220 to FR1225):

- Positions are a pure function of the snapshot's path tree and symbol names: ordered strips of directories, then files, then symbols, each in name order, every symbol the same area, overloads ordered by declaration line. Edges never move a node. The server computes them when it builds the Galaxy payload, in 0.1 s at 250,000 symbols, and the same snapshot gives byte-identical positions in every browser, on every machine and on every run.
- The payload carries each position as 16 bits per axis within the map's square frame. Its header names `format` 4, and the cache file is `galaxy-v4-<snapshot>`, so a `galaxy-v3` payload is rebuilt once and not read.
- The browser runs no simulation: the first frame is final. The pause or resume layout control, the IndexedDB layout cache (`proofmesh-galaxy`), the warm start from the previous layout and point dragging are removed. A search or an area filter keeps every point where the whole map has it.
- A commit moves only what it touches. The number of strips need not be whole and each item takes the strip its weight's midpoint falls in, so one more file or symbol moves at most a boundary item rather than reflowing the rest. On TypeORM (7,033 symbols), a commit that adds a three-function file, changes a body, adds a method and deletes a function moved 0.20% of the shared symbols more than 2% of the map's width (all in the directory it touched), and the median symbol 0.02%.
- The Galaxy's legend says that position shows containment (directory, then file, then name) and that only drawn lines are relationships (FR068). The other views still say position carries no meaning.
- The Observatory benchmark (#41) marks final positions when the Galaxy marks itself ready (`.galaxy[data-ready]`), measures stability from the positions in the payload each page receives (the IndexedDB layout is gone), and writes synthetic galaxies in format 4, laid out by the server's own layout code (`packages/proofmesh/dist/layout.mjs`, built by `pnpm build`).

The JSON and Markdown name the hardware, its load average, the browser build, the viewport, the WebGL renderer and the ProofMesh commit. A software renderer is named and checked against the budgets' software column.

Tests and paths across repositories, chains through a third, and a public pair (part of #28; FR1260 to FR1264):

- `find_tests` takes `include_workspace: true`: the tests in the other repositories of a workspace that reach the subjects through a package this repository builds are listed after its own, each with `repository`, one deeper than the site that crosses in, and a chain in its own repository that ends at that site. Without it, nothing changes.
- `trace_paths` takes `include_workspace: true`: `source_id` or `target_id` may be a symbol of another repository of the workspace, by its id there, and a path crosses a `package_symbol` link from its call site. Nodes of another repository carry `repository`, a crossing hop has the rule `package_symbol` and the link's basis, and a lean row ends `repo=<name>@<commit>`. Dispatch is not followed across repositories.
- A chain continues through any number of repositories: `analyze_impact` and `find_tests` follow from what they reach in one member into the members that use a package that member builds (a library, an application that publishes a package, and an application of that), and `trace_paths` follows a path through each.
- `sh bench/parity/xrepo.sh` measures scenario 4 on a public pair, Excalibur 0.32.0 and its sample game sample-tactics, pinned by commit and never committed: 400 of 400 application call sites into the library that the TypeScript checker counts resolve to the library's symbol (100%), with no extra rows.
- A package published from a subdirectory of a monorepository (`packages/geo/package.json`) resolves to that package's symbols alone, now tested (FR1265).
- The core `tools/list` is 19,758 bytes (14 tools), at most 20,000.
- Not done yet: ecosystems other than npm, and dispatch across repositories.

A cold build in less memory and time, with the same facts (part of #32; FR1240 to FR1244):

- The index host and every JavaScript adapter start with `--max-semi-space-size=4 --heap-growing-percent=25`, ahead of their heap limit. V8's defaults let each hold about 490 MB on the parity fixture for 60 to 160 MB of live data. A heap flag given to the CLI still wins.
- Capture no longer fsyncs each object as it writes it. The objects are fsynced on the thread pool while the adapters run, and the index waits for that before it seals the snapshot, so they are durable before anything published cites them. One fsync per file was most of capture's time.
- The TypeScript adapter (0.2.6) keeps a byte-offset map only for files with non-ASCII text (it kept 4 bytes per character for every file), turns each file's facts into JSON text as soon as the file is read, and writes a reply a megabyte at a time. Its facts are byte for byte the same.
- A staging snapshot keeps up to 64 MB of SQLite pages in memory (it kept 2 MB), so writing relationships rereads fewer index pages. The sealed file is byte for byte the same.
- Parity fixture (`bench/parity`, medians of 3): full build 8.8 s to 5.3 s, peak memory of the largest process 522 MB to 358 MB. Graphify took 3.5 s and 3.3 s in the same runs, so ProofMesh is still slower.
- Graph benchmark (Orbit, 874 files, medians of 3 on a loaded machine): the largest process peaks at 1.3 GB, down from 1.7 GB, still over the 600 MB bar; `tsc --noEmit` alone needs 1.2 GB for that program. A cold build at load 9 took 24 s, down from 30 s. Q1 to Q13 are unchanged.
- Not done: the store size bar (the snapshot holds rows and indexes, not source text, so it needs a format change), and bounding TypeScript memory per program below what the checker needs.
- Upgrade note: the TypeScript adapter is 0.2.6, so the next index of a TypeScript repository reanalyses every file once.

A read-only move plan, and every site of a reference in C# and Python (part of #38; FR1280 to FR1289):

- `plan_move` (the `extra` MCP profile) lists every site a move of a file, or of a top-level symbol to another file, must change, one row per file and line, and changes no file. For a file: each statement that imports or re-exports it, with its specifier as written and as it must be in the same style, its own relative imports that its new place changes, and, inferred, strings and doc mentions that name its path. For a symbol: the statements that import it or re-export its file, the old file's use that will need an import, and what it uses that its new file must import. A test moves the fixture's file as planned, indexes again and finds no TypeScript error, no unresolved import and no stale mention.
- The C# adapter (0.1.1) gives a `references` row every site of a repeated use (protocol 1.3), so `plan_rename` lists each line where a C# member is read twice in one method.
- The Python adapter (0.1.1) records a use of a repository class or function as a type or a value as a `references` row, at every site, and `plan_rename` lists the names of a `from m import a, b`. Before, a Python rename plan listed only calls and the declaration.
- `plan_rename` says a symbol is public when the entry imports it under an alias and exports the alias, and places a call whose receiver has the method's name on the line above at the method's name.

Evidence in one request: the Proof lens (part of #45; FR1180 to FR1187):

- Opening a symbol made four requests in series (`galaxy/symbol`, `get_symbol`, `get_relationships`, `read_evidence`), and an edge's evidence a second `get_relationships`. `get_symbol_card` (the `extra` MCP profile) now answers a symbol's card in one read-only request: the symbol, its verified declaration, and the first rows of each side, each with its call site's lines, the cited span, its basis, resolution and reason, and each side's total. It is bounded like every tool: `max_rows` per side, `max_bytes` for the whole answer, and `direction` with `offset` for the next rows. A Galaxy point's `galaxy/symbol` request carries its card, so a point also opens with one request.
- Explore's drawn neighbourhood is replaced by the Proof lens: callers, the focus and callees as rows, each at its call site and marked `observed`, `inferred` or `unresolved · <reason>` in words, glyph and marker style. Opening a row's evidence asks the server nothing; the code panel highlights the cited span. Evidence that fails its integrity check keeps its row, and the panel says the source is unavailable. A hub shows its first 24 rows per side with the count, and pages the rest in as the list scrolls.
- Keyboard: an opened symbol takes the focus; ↑ ↓ move between rows, ← → between columns, Enter opens the evidence, `f` explores from the row. Resting the pointer on a row or a Galaxy point for 80 ms prefetches its card, one at a time. The lens asks for a path from the focus and shows it as a chain of hops, each with its call site (`trace_paths` now gives each hop of a path its `site`), labelled by its weakest hop.
- `bench/observatory/evidence.mjs` times the click to the evidence text, warm and on a page's first open, counts the requests, and records the machine's load; `--check` holds it to 150 ms warm and 400 ms first open at p95, and one request per open.

Concept search: `search_concepts` ranks the symbols and files that match a description, with no model (#27; FR580 to FR585):

- A new core-profile tool. It takes `text` (up to a whole issue body), `kinds`, `path_prefix`, `include_tests` and `limits`, and answers 20 symbols and 20 files by default, each with `file:line`, a score and up to five matched terms; a symbol raised by graph proximity names the match it is near in `via`. Lean by default over MCP. The core `tools/list` is 19,680 bytes with it (14 tools), under the 20,000-byte bound.
- Snapshot format 0.13 adds the term index (`term`, `term_file`): each indexed file's identifier words (camelCase, PascalCase and snake_case split, a multi-word identifier also whole), comment, docstring and string words, and path segments, by line. It is filled at seal time; the next index rebuilds every snapshot, and an older snapshot answers `search_concepts` with no rows and a limitation saying to index again.
- Ranking is BM25 with a light stemmer and adjacent-word phrases, plus a bounded boost one or two resolved relationships from the five best matches; `docs/proofmesh/mcp.md` states the formula. Test code ranks below production code unless `include_tests` is true, generated files are left out, and a text keeps its 32 heaviest terms.
- `bench/localise` scores it on 50 pinned SWE-bench Lite instances against a BM25 baseline the same harness computes (its README has the results).
- `PROOFMESH_PYRIGHT=off` indexes Python without Pyright: declarations and imports as before, every call unresolved, and the adapter's toolchain says `pyright: off`, so no snapshot or cached fact of the other mode is reused. The benchmark uses it to keep indexing time bounded.

A body edit in a TypeScript file reanalyses that file alone (part of #31; FR1120 to FR1126):

- The TypeScript adapter (0.2.5, protocol 1.3) now declares one unit per file, keyed by a digest of every program file's outline: its text with each body no other file can observe left out (a constructor's, unless its class has a property with neither a type nor an initializer; a setter's; any other function's whose return type is written), and with any body kept that holds a route, a resolver map, an `import()`, or, where the program has them, a `new` (`@pulumi/pulumi`) or an `a.b.c()` call (`@prisma/client`). No body left out is typed while signatures are printed, so the literal types it makes cannot reorder a later signature's union. An edit inside such a body reanalyses only the edited file; an edit to a signature, an export, an import, an inferred-return body, any JavaScript file, or the file list reanalyses every file, as before. On the parity fixture, adding a statement to the constructor of `src/error/TypeORMError.ts` now reuses the facts of 504 of 505 files (it reused 1).
- TypeScript local ids of declarations, Pulumi resources, inline route handlers and GraphQL resolvers no longer carry a byte position (`src/a.ts#function#a:f`, with `~2` for a second one of one kind and name in a file), so a body edit that moves later declarations leaves other files' cached facts valid. Local ids are not stored; a snapshot's rows are those a clean index of the same tree seals, with the same snapshot id, which `fast-rebuild.test.ts` checks for each kind of edit.
- The adapter no longer types every `new` expression of a program that has no `@pulumi/pulumi` in it, nor `a.b.c()` calls where no file imports `@prisma/client` (1.3 s of CPU of each index of TypeORM on a loaded machine), and the core hashes declaration bodies (FR130) without compiling a Unicode expression per name (0.9 to 4.6 s, by load, now 0.1 to 0.5 s); both give the same results as before.
- The core refuses two units with one id as a protocol error; they shared one cache key, so one file's facts could be replayed for another.
- Upgrade note: the TypeScript adapter is 0.2.5, so the next index of a TypeScript repository reanalyses every file once.
- Not done: storing a rebuild as a delta (each snapshot is still a full SQLite copy, so a one-edit rebuild still grows the data directory by about 42 MB on TypeORM), bounding a signature change to the files that use it (FR-002 of #31), deciding `unchanged` before any adapter starts (FR-004), and the Orbit graph benchmark (scenario 5).

Code found by its shape, limited by the graph (part of #37; FR1060 to FR1067):

- New tool `search_structure` (profile `extra`, lean over MCP) takes a code pattern in ast-grep's syntax (`$X`, `$$$X`, `$_`, a repeated metavariable matching equal code) and matches it over the Tree-sitter grammars the syntax tier already ships, with no new dependency: TypeScript, TSX, JavaScript, Python, Go, Rust, Java, C, C++, C#, Ruby, Kotlin, Scala, Swift, Bash and HCL. Each match is a lean row `<enclosing name> <path>:<line> <first line of the match>`, paged with a cursor, with an exact total.
- `scope` keeps only the matches whose enclosing symbol `trace_paths` reaches from a symbol (`reachable_from`), that reaches a symbol (`reaching`), or that sit in files importing a file (`importing`). ast-grep cannot express this.
- A pattern that does not parse is refused as `INVALID_ARGUMENT` with each syntax error and the pattern's syntax tree, in the format of ast-grep's `--debug-query=pattern`.
- A pattern is a resource surface: the match runs in the syntax adapter's own process, stops at `timeout_ms` with what it found, and is killed a second later if it does not. Patterns are at most 4,096 characters, files over 1 MiB are not parsed, at most 64 MiB of source is read per search, and nothing in a pattern or a file is ever run. Matches are against the snapshot's captured content, never the working tree.
- `bench/structure` runs 29 patterns through `search_structure` and the pinned ast-grep 0.51.1 CLI on the parity fixture and on `fixtures/`, and checks the scoped search against `trace_paths`. Every match set is identical, and so is the scoped one (SC-001, SC-002). Not done: SC-003. The WebAssembly matcher in a Node process takes several times longer per pattern than ast-grep's native, multi-threaded CLI on the parity fixture, so the latency target is not met.

A Composer `require-dev` package is for tests only (closes #180; FR1040):

- A `require-dev` entry was recorded like a `require` one, with no scope, so a main source (`src/`) bound names of a package it may only use in development. Its `depends_on` or `depends_on_package` row now carries `detail.scope` `test`, as Cargo's `dev-dependencies` do. A main source's call or `use` into such a package keeps its row (`outside_capability`); a file under the project's `autoload-dev` directories (or `src/test` and the like) still binds it.
- Upgrade note: `RESOLUTION_VERSION` is 6, so no snapshot bound by the earlier rules is reused.

A type query of a function or variable is a reference (closes #175; FR1010):

- `typeof f`, where `f` is a repository function, method or variable, recorded no `references` row: the TypeScript adapter kept a type query only of a class, interface, enum or type alias. It is now a `references` relationship from the symbol that holds it, `detail.use` `typeof`. So a function used only in a type has an inbound use, and `find_unused` no longer lists it: on the parity fixture, `EJSONserialize`, `EJSONdeserialize`, `parse` and `stringify` of `bson.typings.ts` (used only in the type of `EJSON`) left Q10, whose precision went from 95% to 100%.
- The TypeScript adapter is 0.2.3, so facts cached by 0.2.2 are not replayed.

A TypeScript property read or written is a reference (closes #182; FR1020, FR1021):

- Reading a property (`this.expressionMap`, `queryRunner.connection`, `user.id`) recorded nothing, and a property that held no function was not even a symbol, so `find_hubs`, `find_unused` and `analyze_impact` could not see who used it. Each property of a class or an interface, a constructor's parameter properties included, is now a symbol of kind `property` (`a:Box.value`), and its reads and writes through `x.name` are `references` relationships from the symbol that holds them, `detail.use` `value`, `detail.access` `read` or `write` (an assignment, a compound assignment, `++`, `--` or `delete`).
- One row per user, property and access, citing every site of that access as evidence (protocol 1.3 `sites`, #190): two reads in one function are one row with two sites, and a write by the same function is a second row.
- What lies inside a property's declaration (its type, initializer and decorators) is now used by the property rather than by its class, as for a method.
- On the parity fixture `find_hubs` now ranks `BaseQueryRunner.connection` among the ten hubs, and Q13 goes from 7 to 8 of 10. The property counts equal the truth's (`connection` and `QueryBuilder.expressionMap` 158 users each), but `expressionMap` ties `connection` at the cut, and `Document` and `EntityMetadata` rank above both because each property typed with them now counts as a user where the truth counts the file.
- The TypeScript adapter is 0.2.4, so cached facts are not replayed. Snapshots gain a symbol per property and a row per property, user and access. A shorthand destructuring of a property (`const { connection } = queryRunner`) is not yet a reference to it.

A keyboard-first command palette for Observatory (issue #43; FR1140 to FR1146):

- `Control+K` or `⌘K` (from anywhere) and `/` (wherever typing is not text) open one palette of symbols, files and commands. Symbols and files are ranked by exact name, then prefix, then substring, then qualified name or path; the first 30 are listed and the palette says how many more match. A one-character query lists commands only and says symbols wait for two characters. Enter on a symbol opens it in Explore with its evidence and moves focus to the evidence panel; on a file it opens the file in the Map.

Each tab shows its key, which `aria-keyshortcuts` also carries; the keys act only while focus is not in a field.
- The name index is built once per snapshot in a Web Worker, from the Galaxy payload, which now also lists the analysed files (`files` in its header; the cached payload is rebuilt once, as `galaxy-v3`). `bench/observatory/frames.mjs` also times the palette: on a synthetic TypeScript repository of 50,000 symbols, typing to results shown took 18 to 19 ms at the 95th percentile in three of four runs (one run had a single 190 ms sample while another index ran on the machine); at 250,001 symbols, 17.6 ms, and no main-thread task over 50 ms while `initialize` was typed a key at a time. Both synthetic repositories have no links between symbols.
- `/` no longer moves focus to the search box; Tab reaches it as before. The palette is a modal dialog whose combobox announces the highlighted option, Escape returns focus where it was, and repository text in it is escaped as everywhere else (FR065). `fixtures/ts-typeorm` gains `src/data-source.ts`, a `DataSource` shaped like TypeORM's, which maps no table.

A task context map: the code around a focus, ranked, within a byte budget (issue #33; FR920 to FR924):

- `get_context_map`, in the `data` tool profile and lean by default, takes a focus (`paths`, `symbols`, or a diff from `base`), a `budget_bytes` (default 4,096) and a `max_depth` (default 2). It answers one row per declaration around the focus, in both directions, `<name> <path>:<line> <relation> depth=<n>`: what calls, implements, imports, references or tests the focus, and what the focus calls, implements, imports and references, with dispatch followed and candidate edges marked ` inferred`. A diff's changed declarations are rows marked `changed`. The answer never exceeds the budget, and a cursor pages the rest.
- The rank is deterministic and stated in `docs/proofmesh/mcp.md`: by depth, observed rows before inferred ones, then a file's first row before any file's second, with what the focus uses alternating with what uses it, each by relation strength, then weight, path and line. A row is inferred when any hop of its chain is.
- The parity benchmark reports the map's inbound and outbound shares at 4,096 and 16,384 bytes beside aider's repository map. On the TypeORM fixture at 4,096 bytes it names on average 62% of each target's inbound files and 81% of its imports; aider's 1,024-token map names 1% and 47%.

A read-only rename plan, every site to change, seams included (part of #38; FR980 to FR988):

- New tool `plan_rename(subject_id | key, new_name)` (profile `extra`; core's `tools/list` is unchanged) lists every site a rename must change, one row per file and line, and changes no file. Code sites are `observed`: the declaration, calls, references, import and export specifiers through re-exports and export aliases, a shorthand destructuring, a recursive call, and the implementations and overrides that must be renamed together (`must_rename_together`). On the ten pinned symbols of TypeORM, the parity fixture, and of the new `fixtures/rename-parity`, they equal the TypeScript language service's `findRenameLocations` (1,682 of 1,682 sites on TypeORM).
- Seams are `inferred` rows with their kind and rule, never certain: `doc_mention`, `route` (OpenAPI `operationId`, MVC conventional routes), `rpc` (gRPC servers), `graphql` (resolver maps), `ffi`, `serialised_key` and `di_key` (a string literal that is exactly the name, by its place). Unresolved calls of the same name are listed apart under `possibly_affected`. A symbol a package's public entry exports carries `public export: consumers outside this repository are not listed`, unless `include_workspace: true` lists the calls and references of the other members of a linked workspace (FR902) as sites with their repository. New fixture `fixtures/rename-seams`.
- Adapter protocol 1.3 adds an optional `sites` array on a relationship, further evidence of it in the same file. The TypeScript adapter (0.2.2) speaks 1.3: a `references` row now holds every site of the use, not only the first, and a shorthand destructuring of a repository member and its local's uses are references to that member. Assertions, ids and edges are unchanged; the next index rebuilds. Not done: `plan_move` (FR-002 of #38), and every-site references in the C# and syntax tiers.

The parity benchmark's aider step is offline, and its maps are the same in every run (closes #187 and #191; FR1100 to FR1102, FR1110 and FR1111):

- aider 0.86.2 downloaded model prices into the shared `~/.aider/caches` when that file was missing or more than a day old. `aider-map.py` now runs aider with a HOME of its own, removed when it ends, holding the price file bundled with the installed litellm, written fresh, so nothing is downloaded and `~/.aider` is untouched. Any network connection or name lookup in the step fails it: `not run: ... aider tried to reach the network (<host>)`.
- aider's maps differed between runs on one fixture. tree-sitter 0.25 returns a capture's nodes in an order that depends on memory, aider counts each capture's last node twice, and its edge weights depend on set order, which `-I` left unseeded. The harness now passes the captures in source order, gives aider file names relative to the root, and runs it with `PYTHONHASHSEED=0` (`-s -P` in place of `-I`); aider's ranking is unchanged. Each run makes every map again in a second copy of the fixture and `parity.md` says whether they are all the same. With the order fixed, aider's mean shares at 4,096 tokens read in 2% out 69% (in 3% out 68% before); the README's aider cells are from two runs of the new harness, equal in every score row and every raw map.

Two parity benchmark runs at once no longer break each other (closes #177; FR1030 to FR1032):

Bounded adapter memory, and progress while indexing a large repository (closes #6; FR270 to FR277):

- A file reports `resolved_calls` `partial` when a call site matches no occurrence, and `unsupported` with `imports` where the syntax tier lacks the language or cannot be reached (FR166, FR170).
- The index is read one document at a time, in memory that grows with its definitions, not its size; `proofmesh scip add` too (FR164). An index with a document before its metadata, or a length longer than the file, is refused; a document is read again only while the index file is unchanged.

Build graph, Maven and Gradle (part of #13):

Stable symbol keys (#15):

- Every tier names a declaration by one qualified name per language: the declared package or namespace for C#, Java, Kotlin, Scala and PHP (`com.acme.Shop.add(int)`), `<path>:<containers>.<name>` for the rest, with a Go receiver, a Rust `impl` target (and its trait, `X.<Display>.fmt`) and a C++ out-of-class owner as the container, a Go struct or interface kept as such, parameter types on overloads, and a C or C++ prototype merged into its definition (FR146). A Python property setter is `C.x(value)`.
- `stable_key` is unique in a snapshot: the core tells any remaining duplicates apart by `~` and a hash of their text, so a new duplicate renames none, and records every one in the snapshot meta. Snapshot format 0.8 adds a unique index on it, so the next index of every repository rebuilds, and the keys of syntax-tier and SCIP symbols change once (FR147).
- The SCIP importer takes each definition's name, kind and span from the syntax tier's declaration of it, so naming an index changes no key and no `body_hash` (FR148).
- `get_symbol`, `get_relationships`, `analyze_impact`, `find_tests` and `get_memory` take `key`, and `trace_paths` takes `source_key` and `target_key` (FR149).
- `get_memory` lists a reference that matches several symbols under `ambiguous_refs` with their keys (staleness `ambiguous`), and reports `tier_changed` when only the tier that analysed a referenced file changed (FR150). A fingerprint accepted before still reads: it is the relationships part alone. Names changed with format 0.8, so a note reference written in the older form reports as missing, once, with that explanation; rewrite it (notes are not migrated).

Language census (#3):

Symbol identity across change (#7):
