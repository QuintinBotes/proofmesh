# Compatibility

| Contract | Version | Policy |
|---|---|---|
| MCP envelope and tool schemas | 0.1 | `schemas/envelope.schema.json` and `schemas/tools/*.json`. The server validates every answer against them before sending it. A field is added before anything that reads it depends on it; a field is removed one minor release after it is marked deprecated in its schema description. |
| Adapter protocol | 1.3 | `schemas/adapter-protocol/`. Semantic versioning (A22). The core accepts every 1.x adapter and strips unknown optional fields from newer minors; a different major is refused with a message naming both versions. |
| Snapshot file format | 0.13 | `schemas/snapshot-format/`. A snapshot is sealed with the format it was built in; a new format changes snapshot identity, so the next index rebuilds. Older sealed files stay readable until the format they use is removed, which is announced one minor release ahead. |
| Link file format | 0.3 | `schemas/link-format/`. As the snapshot format. |
| Bundle format | 0.1 | `schemas/bundle-format/`. A bundle names its format in `manifest.json`. `proofmesh bundle check` verifies bundles of this format and refuses another format rather than guessing; a format change is announced one minor release ahead, so a bundle kept as a record can still be checked with the release that wrote it. |
| Snapshot export format | 0.1 | `schemas/snapshot-export/`. A file `proofmesh snapshot export` writes starts with the line `proofmesh-snapshot 0.1` and carries a snapshot of the snapshot file format above. `proofmesh snapshot import` reads this format only and refuses another rather than guessing, and also refuses a snapshot of another snapshot file format; carry snapshots between data directories of the same release. |
| Catalog | 0024 | `schemas/catalog/`. Forward-only migrations, 0001 to the version shown, applied on open; a catalog newer than the CLI refuses to open. Back it up before upgrading (`proofmesh backup`). |
| Node.js | 22.13 or later | The active LTS line. |
| .NET | 10 | Only the C# adapter needs it. |

`list_queries` returns the contract versions above as `contract`, the manifest a client can check before it relies on a schema. A test fails when this table and the code disagree.

Removed without a deprecation period: the `detail.inferred` values `name_match` and `package_directory` that constrained name matching wrote on a bound relationship row (#61). They were a stand-in for `basis` (FR188), which is derived from the row's resolution, origin and detail and so is on every row; read `basis` instead. A row's `detail.rule` stays. `detail.inferred` itself is still written by adapters and still makes a row `inferred`. The resolution version moved from 2 to 3, so snapshots built before are not reused and the next index rebuilds.

Changed behaviour of C# test recognition (roles, protocol 1.1): a type that holds an xUnit, NUnit or MSTest attribute, and its members, are test code wherever the file sits, where only a `*Tests.cs` name or a test project made them so before; and `find_tests` lists only the attributed methods of a C# file that has any, where it listed every symbol of a test file. A C# file with no attribute is decided by its path and project as before. The C# names `Contest.cs` and `Latest.cs` still match the existing `Tests?.cs` file rule, which is case-insensitive and was not changed.

Changed default of `proofmesh mcp` (#26): it lists the `core` tool profile, 13 of the 30 tools, with the per-field descriptions left out of their listed input schemas. Tool names, input schemas, validation and envelopes do not change. `proofmesh mcp --tools all` lists every tool as before; a call to a tool that is not listed is `INVALID_ARGUMENT` naming the profile that lists it (docs/proofmesh/mcp.md).

Added to the MCP envelope and the `analyze_impact` schema (#159), in every envelope, `compact` included: `line` and `relationship` on each `analyze_impact` dependent, `site` on a dependent whose relationship is recorded in another file (it was there only for files reached through imports), and `completion.total` on `analyze_impact` and `find_tests` answers. The change is additive. No field is removed or renamed, no value changes meaning, and envelope version 0.1 stays. A client that rejects unknown fields must accept the new ones before it upgrades. Lean text is unchanged.

Added to the adapter protocol in 1.3 (#38): an optional `sites` array on a relationship, further ranges in the same file that are evidence of the same relationship. The core writes each as one more evidence row of the assertion; the assertion, its id, its edge and its first `site` stay as before. A 1.0 to 1.2 adapter sends none and is read as before. The TypeScript adapter (0.2.2) now speaks 1.3 and gives a `references` row every site of a use after the first, so `get_relationships` lists the same rows with more `site.evidence` ids, and a shorthand destructuring of a repository member (`const { escape } = driver`) and the uses of its local are a reference to that member. Snapshot identity changes with the adapter version, so the next index rebuilds.

The C# adapter (0.1.1) and the Python adapter (0.1.1) speak adapter protocol 1.3 too (#38): a C# `references` row now carries every further site of the same use, and Python records `references` for a use of a repository class or function other than a call (FR1286, FR1287). `get_relationships` lists more `references` rows for Python and more `site.evidence` ids for C#. Snapshot identity changes with the adapter versions, so the next index rebuilds.

Added to the MCP envelope (#39): `snapshot.imported` (`origin`, `imported_at`, `stale_count`), present only on an answer from a snapshot imported with `proofmesh snapshot import`, and `snapshot_export` in `list_queries`' `contract`. The change is additive and envelope version 0.1 stays. Lean text from an imported snapshot has `imported` after `current` or `stale` in its first line.

Changed between `proofmesh view` and its browser (#44): the Galaxy payload (`/api/v1/galaxy`) is format 4, which adds a positions section and names `format` in its header. It is not a public contract: the server and the Observatory it serves ship together. The snapshot file format does not change, because positions are derived from the snapshot's paths and names and are not stored in it; a data directory keeps its snapshots, rebuilds each Galaxy payload once as `cache/galaxy-v4-<snapshot>`, and no longer reads the `galaxy-v3` files, which can be deleted. A browser's old `proofmesh-galaxy` IndexedDB database is no longer read or written.

Changed between `proofmesh view` and its browser (#46): the Galaxy payload is format 5. Its areas are a file's first two directories (they were its first three), and it adds the layout's cells (four sections and `cells`, `cell_names_bytes` in the header) and the bundles between areas (`bundles`, `relationship_types` in the header). A new route, `/api/v1/galaxy/bundle`, lists the relationships of one bundle. Neither is a public contract; a data directory rebuilds each payload once as `cache/galaxy-v5-<snapshot>`, and the `galaxy-v4` files can be deleted. The snapshot file format and every MCP answer, `analyze_impact`'s `by_area` included, do not change.

Deprecations are listed in CHANGELOG.md under the release that announces them.
